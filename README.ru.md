# HotS Twitch Companion v0.6.0

Портативный Windows x64 EXE с минималистичным тёмным сине-фиолетовым интерфейсом без игровых декоративных элементов. Реальный GUI создаётся локальными HTML/CSS/JS, встроенными в исполняемый файл средствами `go:embed`. Для отображения отдельного desktop-окна используется установленный в Windows Microsoft Edge в режиме `--app`; без Edge откроется браузер по умолчанию. **[Read in English](README.md)**

## Возможности

- **Интерфейс на английском и русском** — переключение в «Настройках» или мастере первого запуска. Сообщения журнала и ошибки сервера следуют выбранному языку.
- **Настраиваемая длительность Prediction** — время приёма ставок (1–30 минут) выбирается в настройках, как выбор длительности в интерфейсе Twitch Predictions. По умолчанию 2 минуты.
- **Настраиваемые тексты Prediction** — заголовок и названия вариантов меняются в настройках; пустые поля используют значения по умолчанию для языка.
- **Проверка папки реплеев** — в настройках есть кнопка проверки папки (стандартной или своей) с подсчётом найденных `.StormReplay`-файлов.
- Toon Handle — это не BattleTag, а уникальный ID аккаунта Blizzard из реплея (например `2-Hero-1-123456`); виден в «Истории матчей» и нужен только при неуникальном нике.
- **Режим симуляции по умолчанию** — весь конвейер работает без затрагивания реальных баллов, пока реальные Predictions не включены явно.
- MPQ-парсер реплеев только на чтение (zlib/BZip2) по публичной документации формата — без DLL-инъекций, хуков, драйверов и чтения памяти игры.

## Компактное окно и масштабирование Windows

Приложение теперь открывает Edge в отдельном окне **1024×800** вместо 1440×950. Это начальный размер, окно по-прежнему можно менять. Отступы и размеры карточек уменьшены без повсеместного уменьшения шрифта; в узком окне основные элементы перестраиваются в одну колонку.

В CSS добавлены адаптивные правила для узких окон и эффективной ширины, возникающей при масштабировании Windows **125–150%** или увеличенном масштабе браузера. Главное действие «Остановить мониторинг» визуально отличается от запуска. Пока запрос выполняется, управляющие кнопки становятся недоступными и показывают индикатор работы; после завершения или ошибки они возвращаются в обычное состояние. Учтена настройка уменьшенной анимации ОС.

Автоматические проверки покрывают размеры по CSS-правилам и состояние кнопок, но не заменяют ручную проверку реального отображения Edge на мониторах с 125–150% DPI.

## Упрощённый мастер первого запуска

Мастер первого запуска теперь состоит из **трёх коротких шагов**: (1) выбрать своего игрока из реплея или ввести ник вручную, (2) подключить Twitch при необходимости, (3) запустить **безопасную симуляцию**. Настройка Twitch **необязательна для симуляции**: без Client ID на втором шаге можно просто нажать «Далее». Реплей также можно не проверять, если ещё не было завершённой игры.

Client ID и проверка реплея доступны в раскрывающихся блоках вместо длинных инструкций. На последнем шаге одна главная кнопка «Запустить симуляцию», а внизу есть «Завершить без запуска». Запуск принудительно сохраняет `realMode=false` до вызова автоматизации; при запущенном реальном мониторинге мастер не меняет режим, а требует сначала остановить его на главной. Если запуск завершился ошибкой, мастер остаётся открытым и не помечает настройку завершённой.

Мастер не изменяет Go API, процесс авторизации Twitch и формат файла конфигурации. Язык можно сменить компактным переключателем RU/EN в заголовке мастера или в «Настройках».

## Простые настройки

На вкладке **«Настройки»** теперь видны три блока: Twitch (состояние и подключение), Heroes of the Storm (ник и выбор игрока из реплея по запросу) и Prediction (длительность, предпросмотр и **явный переключатель реальных ставок**).

Технические поля — Client ID, Toon Handle, путь реплеев и собственные тексты Prediction — перенесены в раскрывающиеся «Расширенные настройки». Данные не удалены и продолжают сохраняться в прежнем формате. Если нажать «Подключить Twitch» без Client ID, приложение само раскроет расширенные настройки и установит фокус на нужном поле.

Панель сохранения остаётся доступной при прокрутке и показывает несохранённые изменения. Реальные Predictions по-прежнему требуют явного подтверждения при первом включении; при выключении галочки приложение предупреждает, что режим остаётся активным до сохранения. Язык интерфейса доступен непосредственно вверху настроек и сохраняется отдельно.

## Минималистичный рабочий интерфейс

Теперь главный экран повторяет утверждённый минималистичный прототип: **одно состояние, одна кнопка Start/Stop, Twitch, Prediction и последний матч**. Журнал перенесён в раскрываемую «Диагностику» внутри истории матчей — со всеми существующими фильтрами. Главная навигация: «Главная», «История», «Настройки». Старые игровые рамки, баннеры, свечения и карточки удалены. Реальный режим по-прежнему заметно предупреждает о баллах зрителей.

## Статусы интерфейса

На экране «Обзор» основные действия **Включить/остановить мониторинг** и **Проверить реплей** вынесены в главный блок. Статусы мониторинга HotS, авторизации Twitch и Prediction показываются отдельно. Сохранённый OAuth-токен не означает подтверждённое соединение: до успешной проверки Twitch интерфейс показывает «Требует проверки». Расчётное время закрытия приёма ставок вычисляется локально и **не подтверждает** актуальное состояние Prediction на Twitch.

## Упрощённая настройка

В мастере и «Настройках» появилась возможность **выбрать игрока из реплея**. Приложение покажет игроков последнего успешно прочитанного матча и подставит ник с Toon Handle — для применения нажми «Сохранить настройки» или продолжи мастер. Если реплеев ещё нет, имя по-прежнему можно ввести вручную.

Блок **«Как это увидят зрители»** в реальном времени показывает будущий заголовок Prediction, варианты ответа и длительность приёма ставок. Это только предпросмотр: он **не отправляет запросы Twitch** и не создаёт реальные Predictions. Предпросмотр также есть на последнем шаге мастера.

Для Twitch по-прежнему нужен твой Client ID от приложения типа **Public** (Client Secret не нужен). В интерфейсе добавлены короткая инструкция, статус авторизации и кнопка копирования Device Code. Общий Client ID намеренно не вшит в исполняемый файл.

В GitHub Actions добавлены проверка синтаксиса JavaScript и тесты мастера на Node.js без сторонних пакетов. Конечным пользователям Node.js не нужен.

## История матчей и диагностика

В **«Истории матчей»** появился поиск по карте, файлу или игроку и фильтр побед / поражений / неопределённых результатов. Показываются **12 последних реплеев**, а не весь архив HotS. Если реплей прочитан, но выбранный игрок не найден, карточка объяснит проблему и предложит перейти в настройки. Ошибка чтения реплея показывается отдельно.

**«Журнал событий»** теперь получает от Go-движка тип события (информация / предупреждение / ошибка), а не пытается определить ошибку по словам в сообщении. Есть фильтры и поиск. Для известных проблем добавлены подсказки: Twitch OAuth, создание и завершение Prediction, отсутствие реплея и другие.

Журнал **не сохраняется на диск**: он содержит до 150 событий за текущий запуск приложения. Это не аудит всей истории и не подтверждение текущего состояния Prediction на стороне Twitch.

## Архитектура интерфейса и доступность

Приложение по-прежнему распространяется как **один Go `.exe`**. Все HTML/CSS/JS-файлы встраиваются через `go:embed`: пользователям не нужны Node.js, npm и отдельный сервер.

Интерфейс разделён на небольшие файлы без сборщика и сторонних зависимостей:

- `core.js` — API, общие данные и навигация
- `i18n.js` — переводы RU/EN
- `replays.js` — история матчей и карточки реплеев
- `diagnostics.js` — журнал событий и диагностика
- `onboarding.js` — мастер, выбор игрока и предпросмотр Prediction
- `app.js` — отрисовка состояний и запуск приложения

Стили разделены на `style.css` (основа), `wizard.css`, `overview.css`, `onboarding.css` и `diagnostics.css`. **Порядок подключений в `web/index.html` важен.** Директива `go:embed` автоматически включает все новые файлы каталога `web/assets/`.

По вкладкам можно перемещаться с клавиатуры клавишами ←/→, Home/End. Текущая вкладка обозначена через `aria-selected`, а фокус перемещается вместе с выбором.

Разработчику для проверки доступны `go test ./...`, `node --test` и `node --check web/assets/app.js`. В GitHub Actions проверяются **все** JS-файлы и выполняются все тесты перед сборкой Windows. Node.js нужен только при разработке, конечным пользователям не требуется.

## Запуск

При первом запуске автоматически открывается **мастер настройки**: он проведёт по шагам — язык, ник игрока HotS (с безопасной проверкой реплея), подключение Twitch и автоматизация — и объяснит, какого результата ждать на каждом шаге. Мастер можно запустить повторно из «Настроек».

1. Останови предыдущий `watch` и старый `.exe`.
2. Запусти `HotS-Twitch-Companion.exe` из release ZIP. Node.js, Go и Python устанавливать не нужно.
3. Следуй мастеру — или настрой вручную: в **Настройках** укажи свой ник в HotS и длительность Prediction, сохрани; **История матчей → Проверить последний реплей** — безопасный тест без Twitch API.
4. В **Настройки → Twitch** укажи `Client ID` Public приложения, сохрани и подключи OAuth Device Code Flow (токен шифруется через DPAPI).
5. Запусти мониторинг с **Обзора** (или из мастера). Симуляция используется по умолчанию.
6. Для настоящих баллов отдельно включи реальный режим с подтверждением в **Настройках**.
7. Кнопка **Выход** внизу завершает процесс сразу. Закрытое окно также приводит к остановке после нескольких минут отсутствия связи.

**История матчей** показывает последние игры: нажми на матч, чтобы раскрыть данные — карту, дату и всех игроков с результатами, твоя запись подсвечена.

## Встроенные защитные механизмы

Локальный интерфейс слушает только `127.0.0.1` на случайном порту, адрес защищён случайным 192-битным сегментом, вызовы API требуют специальный заголовок, POST проверяет Origin/Sec-Fetch-Site, включён CSP, запрещены cross-origin запросы. Токены Twitch не передаются в интерфейс и хранятся через Windows DPAPI; файлы HotS открываются только на чтение, без DLL-инъекций, хуков, драйверов и чтения памяти игры. Ни один из механизмов не гарантирует одобрение со стороны Blizzard.

Логика из старой Go-версии (корректировка MPQ zlib/BZip2, Twitch OAuth, Predictions, наблюдение за `replay.server.battlelobby`/`.StormReplay`) сохранена. Состояние в `%LOCALAPPDATA%\HotSTwitchCompanion` переиспользуется — **не запускай две версии одновременно**. Старый Node.js прототип не совместим по формату state/tokens.

## Сборка из исходников

```powershell
go test ./...
go build -trimpath -ldflags="-H=windowsgui -s -w" -o HotS-Twitch-Companion.exe .
```

Linux cross-compile: `GOOS=windows GOARCH=amd64 CGO_ENABLED=0 go build -trimpath -ldflags="-H=windowsgui -s -w" -o HotS-Twitch-Companion.exe .`

Go 1.23, только стандартная библиотека, без зависимостей. `service.go` — HTTP/UI-обвязка, `main_windows.go` — окно Edge, `core.go` — логика Twitch/HotS, `replay.go` — MPQ декодер, `i18n.go` — каталог сообщений EN/RU, `web/` — интерфейс.

## Проверки

Автотесты MPQ, BZip2/zlib, чтения результата, сохранности файла и локальных API проходят в Linux; `.exe` кросс-компилирован и проверен как Windows x64 GUI PE. **Живой Twitch API и отображение на Windows с реальным HotS пока не протестированы**. Сначала проверь реплеи и симуляцию; не включай реальные Predictions до подтверждения корректности.


## GitHub и CI/CD

Для публикации исходного кода используй архив `HotS-Twitch-Companion-v0.2-GitHub-ready.zip` (без `.exe` внутри). Создай новый GitHub-репозиторий и загрузи **содержимое** архива в корень. Workflow `.github/workflows/windows.yml`:

- на push в `main` / Pull Request / ручной запуск: прогоняет `go test ./...`, собирает Windows x64 `.exe` и сохраняет ZIP в **Actions → Artifacts**;
- на push тега `v*`: дополнительно создаёт **GitHub Release** и прикладывает ZIP + SHA256.

Локальная сборка в PowerShell:

```powershell
.\build.ps1
```

Результат: `dist/HotS-Twitch-Companion.exe` и `HotS-Twitch-Companion-windows-x64.zip`.

Первый релиз (в Git Bash или другом терминале с Git):

```bash
git add .
git commit -m "Publish HotS Twitch Companion v0.3"
git push origin main
git tag v0.3.0
git push origin v0.3.0
```

Перед публикацией проверь `git status` и список отслеживаемых файлов: **не коммить Client Secret, access/refresh tokens или личные файлы HotS**. Конфигурация пользователя и DPAPI-токены в штатной работе находятся в `%LOCALAPPDATA%\HotSTwitchCompanion`, а не в репозитории. Файлы artwork/UI следует публиковать только если есть права на распространение. Название HotS является товарным знаком Blizzard; добавь disclaimer, что проект неофициальный.
