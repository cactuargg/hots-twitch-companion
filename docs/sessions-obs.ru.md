# Сессии, счёт и оверлеи OBS

## Быстрый старт

1. В «Настройки → Основные» выбери своего игрока из реплея и сохрани настройки.
   Toon Handle нужен для автоматического наблюдения за началом матча.
2. В «Оверлеи OBS» включи «Считать матчи». Создастся первая сессия 0–0;
   старые игры автоматически не импортируются.
3. Скопируй URL счёта в источник OBS «Браузер». Начальный размер источника:
   560 × 140, затем расположи его на сцене. Фон за плашкой прозрачный.
4. Для скрытия препиков включи маску и добавь её отдельный URL в другой
   источник «Браузер», поверх захвата игры. Размер источника задай по области,
   которую нужно перекрыть. Стандартная панель непрозрачная; можно загрузить
   PNG/JPEG до 2 МиБ. Под изображением всегда остаётся непрозрачный фон.
5. Companion должен работать во время трансляции. Его можно свернуть в трей.

## Сессии

Сессия не зависит от запуска приложения, полуночи или подключения Twitch.
«Новая сессия» на главном экране архивирует предыдущую и обнуляет текущий счёт.
Матчи и границы сохраняются сразу в sessions.json внутри профиля Companion.
Атомарная запись не публикует новое состояние, если сохранение не удалось.
Повреждённый файл истории не перезаписывается автоматически; ошибка видна в UI.

Закрытие и повторный запуск продолжают текущую сессию. Журнал читает реплеи
независимо от мониторинга прогнозов, без авторизации Twitch и без операций с
баллами зрителей. Копии одного реплея считаются один раз по SHA-256 файла.

Автоматическая принадлежность матча определяется по сохранённому наблюдению
BattleLobby, побайтно совпадающего со встроенным BattleLobby реплея. Это время
наблюдения загрузки, а не точное время начала драфта. Поздний реплей такого
матча попадает в прежнюю сессию, даже если уже нажата «Новая сессия».
Повторное появление одинакового BattleLobby с другим временем фиксируется
как неоднозначность и не используется для автоматического выбора сессии.

Если приложение было закрыто до начала игры, результат восстанавливается из
доступного реплея, но точная граница начала не угадывается. Такой матч показан
в «История → Сессии и матчи» отдельно и не входит в счёт, пока пользователь
не выберет для него сессию. Переименование старого файла не превращает старую
игру в новую: для импорта используется также игровой timestamp из реплея.
Реплеи с отсутствующим игровым временем и без наблюдения начала автоматически
не импортируются. Ошибки чтения показаны в интерфейсе, файл проверяется повторно.

В истории можно отменить последний сброс, начать новую сессию с выбранного
матча текущей сессии с известным началом, перенести матч в другую сессию этого
игрока, исключить его или исправить результат. Исправления помечены вручную.
Фильтр «Только Storm League» пересчитывает отображаемый счёт, сохраняя журнал.
Другой выбранный игрок получает собственную сессию и отдельную историю.

Выключение счётчика сохраняет сессию. Матчи, начавшиеся в период выключенного
счётчика, при включении автоматически не добавляются. Сам по себе выход из
программы такой паузой не является: после запуска пропущенные реплеи проверяются.

## Маска

Быстрые переключатели на главной применяются сразу:

- «Включить маску» включает/выключает источник;
- «Автоматически» управляет видимостью по игровым файлам;
- «Показывать маску» и «Скрыть маску» дают ручное управление.

В автоматике свежий BattleLobby выбранного игрока означает «Загрузка / матч»:
маска скрывается. При появлении соответствующего завершённого реплея возвращается.
По умолчанию выбран фильтр Storm League. Пока режим неизвестен, маска видна.
Сам экран драфта, выход в меню и отмена поиска напрямую не распознаются.
Quick Match определяется только после появления BattleLobby; для игры без маски
до этого момента выключи её вручную. После отмены драфта, задержки реплея или
запуска приложения посреди игры может потребоваться ручное переключение.
Через 100 минут без нового матча состояние возвращается в неизвестное.

Сканирование идёт раз в 3 секунды; реплей ждёт минимум 8 секунд после последней
записи. Поэтому маска возвращается с задержкой после окончания игры. При потере
связи браузерный источник показывает маску; счёт сохраняет последнее значение.
Автоматика проверена на файловых фикстурах, но нуждается в проверке в живом
драфте и реальной сцене OBS для конкретной установки HotS.

## Настройки и локальный сервер

Настройки показаны на одной странице: «Игрок и трансляция», «Оверлеи OBS»,
«Приложение и данные». На широком окне внутри групп две колонки, на узком — одна.
Текст прогноза, оформление оверлеев и прочие поля применяются общей кнопкой
«Сохранить изменения». Оперативные переключатели маски и счётчика, язык и
проверка обновлений сохраняются сразу.
Предпросмотр счёта использует пример 7–3.

Обе версии приложения поднимают сервер на 127.0.0.1:18765. Ссылки с отдельным
случайным токеном сохраняются в профиле и переживают перезапуск. Сервер принимает
только чтение данных оверлеев и не предоставляет управляющий API, историю,
путь к реплеям или токены Twitch. При занятом порте ошибка видна в настройках;
автоматически менять порт нельзя, иначе ссылки в OBS перестанут работать.
В BrowserFallback запросы OBS поддерживают приложение активным, даже когда
вкладка настроек закрыта.

Полный «Сброс Companion» удаляет также sessions.json, историю и ссылки OBS.
Игровые реплеи не изменяются и не удаляются.

## Проверки для разработки

`go test ./...` и `go test -tags 'wails,production,wv2runtime.error' ./...`
проверяют обе сборки. `node --test tests/*.test.cjs` проверяет UI-контракты
и поведение источников при отключении связи.

Дополнительно `node tests/obs-browser-smoke.cjs` запускает локальный тестовый
сервер и headless Edge с отдельным временным профилем: проверяет разделы,
сохранение оформления, ручную маску, назначение сессии и ширину 480 px.
Нужен доступный пакет Playwright (через NODE_PATH или локальную установку).
Скриншоты сохраняются в .research; пользовательский профиль Companion и Twitch
не используются.

## Свой CSS счётчика (v0.10.3)

В «Настройки → Оверлеи OBS → Счёт сессии» добавлено поле «Свой CSS».
Вставь правила и нажми «Сохранить изменения». Стили сохраняются вместе с
профилем и обновляются в источнике OBS автоматически, без копирования в OBS.
Во время ввода отдельный предпросмотр показывает пример счёта 7–3.

Доступны `#score`, `#wins`, `#losses`, `#win-label`, `#loss-label`, `.divider`.
Для изменения цвета цифр используй `!important`, так как выбранные цвета
устанавливаются непосредственно на цифры. Например:

```css
#score { background: #1b1029 !important; border: 2px solid #bd9559 !important; }
#wins { color: #d3a2ff !important; }
#losses { color: #ff858e !important; }
```

Очисти поле и сохрани, чтобы вернуть стандартный стиль. Максимальный размер —
64 КиБ. CSS действует только на счётчик; маска и интерфейс приложения изолированы.
