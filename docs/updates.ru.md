# Проверка и установка обновлений

Эта возможность доступна начиная с v0.9.10. В версиях
v0.9.3–v0.9.9 есть только небольшая ссылка на страницу нового релиза внизу окна.
Для перехода на сборку с установкой обновлений из интерфейса её нужно один раз
скачать вручную. Старые EXE не получают новый код задним числом.

## Пользователю

Раздел **Настройки → Обновления приложения** показывает результат и время
последней проверки. При обнаружении новой версии на главной появляется заметное
сообщение. Кнопка **Проверить сейчас** запускает ручную проверку. После успеха
фоновая проверка повторяется раз в сутки; после ошибки — с увеличением задержки,
начиная с минуты. Ограничения GitHub `Retry-After` и `X-RateLimit-Reset` соблюдаются.

Переключатель **Проверять обновления** сохраняется сразу, независимо от несохранённых
полей игрока и прогноза. Выключение отменяет текущий запрос/скачивание и запрещает
автоматические и ручные проверки, а также новое скачивание. При следующем запуске
выбор сохраняется. Twitch и мониторинг работают независимо от этого переключателя.
Повторное включение доступно в том же разделе.

**Скачать обновление** получает пакет той же редакции: Desktop или Browser. Это
можно делать во время мониторинга. Не прошедший проверку файл не устанавливается.
Старый EXE и профиль во время скачивания не изменяются.

Для **Обновить и перезапустить** нужно сохранить правки настроек, закончить
подключение Twitch, остановить мониторинг и завершить активный прогноз. Если
создание прогноза не подтверждено, сначала проверь Twitch и сними блокировку
создания через главную. Установка сама не отменяет прогнозы и не выбирает исход.

После подтверждения отдельный вспомогательный процесс ждёт завершения приложения,
проверяет освобождение профиля, сохраняет старый EXE и заменяет текущий файл.
Новая копия запускается с тем же профилем. Если создание процесса или подтверждение
старта интерфейса не удаётся, прежний EXE восстанавливается и запускается снова.
Имя и путь запускаемого EXE сохраняются: если имя содержит старую версию, точную
текущую версию смотри внизу окна и в свойствах файла. Существующие ярлыки продолжают
работать. Настройки и сохранённое подключение Twitch не сбрасываются.

Для установки нужны права записи в папку EXE. При их отсутствии остаётся ручное
скачивание со страницы релиза. Приложение не запрашивает повышение прав. Резервная
копия `previous.exe` и технические файлы остаются в соседней папке
`.companion-update-*`; это не файлы профиля. Не удаляй эту папку во время установки.
Если EXE запущен из временной папки (например, прямо из ZIP через Проводник),
установка из интерфейса отключена: сначала полностью распакуй архив в обычную папку.

## Границы доверия

Метаданные получаются по HTTPS только для фиксированного публичного репозитория
`cactuargg/hots-twitch-companion`. Установщик принимает только стабильные версии,
ожидаемые имена пакетов своей редакции и точные ссылки release assets этого
репозитория. Перенаправления загрузки ограничены HTTPS-хостами GitHub и его CDN.
Проверяются размер, SHA-256 из метаданных GitHub и формат Windows x64 EXE. Browser
ZIP читается только для извлечения ожидаемого EXE, без распаковки путей из архива.
Хеш перепроверяется перед передачей вспомогательному процессу и перед заменой.

Это проверка целостности и происхождения через доверенный HTTPS GitHub, а не
независимая цифровая подпись издателя. Текущие EXE не подписаны Authenticode.
Компрометацию аккаунта публикации она не компенсирует. Для независимой проверки
издателя потребуется отдельный подписанный манифест с закреплённым открытым ключом.
GitHub-токены и приватные ключи в приложение не встраиваются.

## Разработчику

`internal/update` владеет HTTP-клиентом, сравнением версий, состоянием проверки,
отменой запросов, проверенным скачиванием и заменой с откатом. Зависимости сети
и времени изолированы для тестов. UI получает снимок состояния через `status.updates`.

POST API: `updates/preferences` (`enabled`), `updates/check`, `updates/download`,
`updates/install` (`confirmed: true`). Все запросы используют существующую защиту
локального API. Настройка `disableUpdateChecks` по умолчанию равна false для старых
профилей. Только отдельный endpoint предпочтений изменяет её: обычные сохранения
настроек, мастер и смена языка сохраняют текущий серверный выбор.
Внутренний `updates/startup-ready` вызывается только обновлённым интерфейсом после
успешного получения и отображения bootstrap. До этого сервер не разрешает запуск
мониторинга: неудача подтверждения не должна приводить к остановке уже начатой игры.

`Engine.BeginUpdate` под `actionMu → mu` проверяет отсутствие мониторинга, активного
и неподтверждённого прогноза и блокирует новый Start после успешной передачи
вспомогательному процессу. Windows-композиция задаёт редакцию, папку EXE и callback
установки. Helper работает без shell и без видимого консольного окна. Новый процесс
подтверждает открытие профиля и успешную загрузку интерфейса через одноразовый файл в staging;
ожидание ограничено 30 секундами. Если подтверждения нет, завершается только этот
новый процесс, после чего восстанавливается прежний EXE. Откат не предназначен для
произвольных несовместимых миграций профиля: будущие релизы должны сохранять
совместимость профилей либо отдельно проектировать откат миграции.

Тесты включают отключение без сети и игнорирование позднего ответа, HTTP rate limit,
повторную проверку после ошибки, повреждение/неверный источник пакета, безопасное
извлечение Browser EXE, запрет установки при прогнозе и несохранённых настройках,
а также реальные Windows-подпроцессы для ожидания выхода, замены, подтверждения
нового запуска и восстановления прежнего EXE при отказе старта. Тестовые процессы
не подключаются к Twitch и используют только временные папки.
